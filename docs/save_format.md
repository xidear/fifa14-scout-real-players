# FIFA14 生涯存档：球衣号码布局与安全写入

本文是改号 App 的依据，全部结论来自对真实存档 `SAVECAREER.*` 的字节分析，并在游戏内验证过（号码改动能被生涯模式正确读取）。

## 1. 存档位置

```
/sdcard/Android/data/com.ea.game.fifa14_row/SAVECAREER.<日>.<月>.<年>.<时>.<分>.<秒>
```

同一目录里可能有多个 `SAVECAREER.*`。App 取 `ls -t`（修改时间最新）的一个。

## 2. 名单行的结构

存档里有一张平坦的「球队-球员」表，每条记录 16 字节：

| 偏移 | 类型 | 含义 |
|---:|---|---|
| +0 | u32 LE | team id |
| +4 | u32 LE | player id |
| +8 | u32 LE | flags（低 8 位含球衣号） |
| +12 | u32 LE | alt |

球衣号换算：

```
jersey = ((flags & 0xFF) >> 1) + 1
flags  = (flags & ~0xFF) | (((jersey - 1) * 2) & 0xFE)
```

即低字节的 bit1..bit7 是 `号码-1`，bit0 与号码无关（保持原值即可）。

注意：**行的起始偏移不是 16 的整数倍**。本存档中为 `offset % 16 == 4`。因此不能假设对齐，应在 0/4/8/12 四种 4 字节对齐下各扫一遍。

## 3. 球队块的发现算法

1. 对每种对齐 `align ∈ {0,4,8,12}`，从该偏移开始按 16 字节步进读 `(team, pid)`。
2. 若 `0 < pid < 30,000,000` 且 `0 < team < 10,000,000`，尝试向后连续读取同一 team 的记录。
3. 连续记录数 ≥ 5 视为一个「球队块」。
4. 同一 team 一般只有一个块；若有多个，取行数最多的。

用这套规则扫描本存档得到 **587 个块**，覆盖 586 支球队；曼城（team id 10）在 `0x5AF4`，24 行。

## 4. 修改与写回

改一个号码只动 flags 低字节：

```
Richards  #11 → #2   flags 0x14 → 0x02
Sturridge #2  → #11  flags 0x03 → 0x14
```

对两个球员做交换时，改号码本身只动 2 个字节（两个球员），但写回时必须重算尾部 CRC，所以整个 3,423,800 字节的存档共 6 个字节变化。

`save_core.py`（研究脚本）里的 `Save.set_jersey / swap_jerseys` 就是这套逻辑。

## 5. 关键：文件属主与权限

游戏以自己 uid 访问 `Android/data/<pkg>`，正常存档的属主/权限是：

```
owner  = media_rw (uid 1023)
group  = u0_a20245 (gid 30245，具体值随安装实例而定)
mode   = 660
```

root 直接 `cp` 会把文件变成 `root:root`。虽然已确认**读档失败的直接原因是 CRC**，仍建议保持原属主/权限不变，避免 FUSE 层的额外问题；本工具会自动继承原文件的 uid/gid 与 660。

正确写法（等价于 App 中 `SaveBackend.write`）：

```sh
OWN=$(stat -c '%u:%g' "$SAVE")           # 先读原文件属主
cp new.bin "$SAVE.app_tmp"
chown "$OWN" "$SAVE.app_tmp"             # 先改临时文件的属主
chmod 660 "$SAVE.app_tmp"
mv -f "$SAVE.app_tmp" "$SAVE"            # 原子替换
```

要点：`chown`/`chmod` 必须作用在**临时文件**上，再 `mv` 覆盖；如果先 `mv` 再 `chown`，中间窗口内游戏可能读到错误属主的文件。

## 6. 尾部 4 字节是整档 CRC（必须重算）

存档最后 4 字节是小端 u32，等于「除最后 4 字节外整个文件」的 CRC-32：

- 多项式 `0x04C11DB7`
- 非反射（MSB-first）
- init `0xFFFFFFFF`
- 最终异或 `0xFFFFFFFF`

两份不同生涯存档都严格匹配。改号后如果不重算尾部，游戏会提示「无游戏存档可用」——这是本工具最早失败的真正原因（不是文件权限，也不是骨架结构）。

写回顺序：先改号码字节 → 对整个数组的 `[0, len-4)` 重算 CRC → 写回最后 4 字节（小端）→ 再落盘。

## 7. 已验证的操作顺序

1. 游戏停在生涯「读取选项」界面（不要已经进入生涯）。
2. App 改号（自动备份为 `<存档>.bak_jersey`）。
3. 在游戏里重新进入生涯（读取存档）。
4. 号码生效。

如果游戏已经在生涯里，改号只会写文件；要让游戏重新读档才会生效（退出到读取界面再进）。

## 8. 为什么不能靠改数据库修 2 号 bug

球衣号不在 `fifa.db` 里，而是保存在存档的 teamplayerlinks 表中；转会时由原生管理器按队内排序重新分配。改号工具是绕过该逻辑的直接手段。相关逆向记录见 `docs/jersey_research.md`。
